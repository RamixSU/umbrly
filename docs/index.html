Документация языка Umbrly

Привет! Это справочник по Umbrly — интерпретируемому (и теперь ещё и компилируемому) языку для Windows. Если вы здесь впервые: не пугайтесь непривычного синтаксиса, через пять минут чтения он покажется совершенно естественным. Идея простая — тип переменной зашит прямо в её имя (INT_, STR_, ARR_…), а команды заканчиваются двоеточием, как заголовки в списке. Дальше — по порядку, от «Hello World» до классов и сборки в .exe.

Привет, Umbrly!

Самая короткая программа на Umbrly — это одна строчка. Вот она, вместе с чем-то чуть более интересным: 

PRINT: "Hello World"

INT_CYFRA = 67
PRINT: "[INT_CYFRA] + [INT_CYFRA] = [INT_CYFRA + INT_CYFRA]"   # 67 + 67 = 134

Что здесь происходит: PRINT: — это команда, двоеточие после неё — не опечатка, а часть синтаксиса (так помечены все команды языка: IF:, WHILE: и остальные). Переменная INT_CYFRA сама говорит о своём типе — никакого отдельного объявления не нужно. А блоки кода закрываются явным словом END, а не отступами, так что случайно съехавший пробел никогда не сломает вам программу.

Переменные и типы

Главная идея языка уместилась в одну таблицу:

ПрефиксТипПример
INT_целое числоINT_CYFRA = 67
FLOAT_дробное числоFLOAT_PI = 3.14
STR_строкаSTR_IMYA = "Вова"
BOOL_логическое (TRUE/FALSE)BOOL_OK = TRUE
ARR_массивARR_XS = [1, 2, 3]
OBJ_объект классаOBJ_HERO = Player("Ая")

Присваивание всегда аккуратно приводит значение к типу переменной (BOOL_ — по истинности, INT_/FLOAT_ — численно, STR_ — через TOSTR). Если приведение невозможно (например, засунуть строку в INT_) — интерпретатор не упадёт молча, а честно скажет об ошибке с номером строки, где это произошло.

Один нюанс стоит запомнить сразу, чтобы не удивляться потом: присваивание массива копирует его, а не ссылается на него — ARR_B = ARR_A создаёт полностью независимую копию. А вот когда массив передаётся параметром функции (своей FUNC или встроенной вроде PUSH) — это уже ссылка на тот же массив, как в Python или JavaScript, поэтому PUSH(ARR_X, v) меняет именно тот ARR_X, который вы передали.

Вывод и ввод

Три способа поговорить с пользователем:

PRINT: "Hello World"
PRINT:                                   # пустая строка

INPUT: "Нажмите Enter..."                # пауза, ждёт нажатия

INT_X = INPUT: "Введите число: "         # ввод с приведением к типу переменной

Подстановка в строки — [выражение]

Пожалуй, самая приятная в использовании часть языка — квадратные скобки прямо внутри строки: 

INT_CYFRA = 67
PRINT: "[INT_CYFRA] + [INT_CYFRA] = [INT_CYFRA + INT_CYFRA]"   # 67 + 67 = 134

Внутри [...] — полноценное выражение: вызовы функций, индексация массивов, арифметика, всё что угодно. Нужны экранированные символы? Пожалуйста: \n \t \r \" \\ \[ \].

Единственная ловушка, о которой стоит знать заранее: если строка должна содержать буквальные квадратные скобки как текст (например, тег вида [OK]), их обязательно нужно экранировать: "\[OK\]". Без экранирования [OK] будет воспринято как подстановка — переменная OK — и приведёт к ошибке разбора. Это единственный раз, когда язык попросит вас быть внимательнее.

Выражения

Приоритет операторов ровно такой, как вы интуитивно ожидаете (по возрастанию): OR → AND → NOT → == != < > <= >= → + - → * / % → ().

  • + со строками — конкатенация: "Привет, " + STR_IMYA
  • / двух целых даёт целое, если делится нацело, иначе дробное: 7 / 2 → 3.5
  • TRUE / FALSE / NIL — литералы
  • Не любите слова? Символьные альтернативы && || ! тоже работают

Условия и циклы

Ничего неожиданного — если вы писали хоть на одном языке программирования, это будет знакомо с первого взгляда:

IF: INT_X > 10
    PRINT: "большое"
ELSE:
    PRINT: "маленькое"
END

WHILE: INT_X > 0
    INT_X = INT_X - 1
END

FOR: INT_I = 1 TO 10           # включительно; необязательный STEP (по умолчанию 1)
    PRINT: "[INT_I]"
END
FOR: INT_J = 10 TO 1 STEP -1
    PRINT: "[INT_J]"
END

BREAK и CONTINUE работают внутри WHILE/FOR именно так, как вы ожидаете. А если случайно напишете их вне цикла — это будет замечено ещё на этапе разбора, а не устроит сюрприз во время выполнения.

Массивы

ARR_XS = [10, 20, 30]
PRINT: "[ARR_XS[0]]"           # 10
ARR_XS[0] = 99                 # присваивание по индексу
PUSH(ARR_XS, 40)
STR_LAST = POP(ARR_XS)
PRINT: "[LEN(ARR_XS)]"

Полный список функций для работы с массивами — PUSH, POP, SORT, SLICE, CONTAINS, INDEX_OF и другие — ищите в справочнике ниже, там же и примеры сигнатур.

Функции — FUNC

FUNC FACT(INT_N):
    IF: INT_N <= 1
        RETURN 1
    END
    RETURN INT_N * FACT(INT_N - 1)
END

PRINT: "[FACT(5)]"             # 120

Параметры типизируются точно так же, как обычные переменные (через префикс имени). Порядок объявления в файле не важен — FUNC можно вызывать до места её объявления, потому что все функции регистрируются заранее, до начала выполнения. Рекурсия ограничена глубиной 256 вызовов — этого с запасом хватает для любой разумной задачи.

Единственное, что стоит держать в голове: присваивание скаляра внутри функции не меняет глобальную переменную с тем же именем — оно создаёт свою, локальную копию. А вот мутация массива через PUSH/SORT/ и подобные функции прекрасно работает и изнутри функции, потому что массив всегда передаётся по ссылке. Если нужно «вернуть» изменённый массив из функции наружу — просто верните его через RETURN и переприсвойте у вызывающей стороны.

Классы — CLASS

Когда простых переменных и функций становится мало, в Umbrly есть классы — без лишней церемонии и без наследования, только поля и методы: 

CLASS Weapon:
    STR_NAME = "кулаки"
    INT_DAMAGE = 5

    FUNC INIT(STR_N, INT_D):
        SELF.STR_NAME = STR_N
        SELF.INT_DAMAGE = INT_D
    END
END

CLASS Player:
    STR_NAME = ""
    INT_HP = 100
    OBJ_WEAPON = Weapon("кулаки", 5)

    FUNC INIT(STR_N):
        SELF.STR_NAME = STR_N
    END

    FUNC EQUIP(OBJ_W):
        SELF.OBJ_WEAPON = OBJ_W
    END
END

OBJ_HERO = Player("Ая")
OBJ_HERO.EQUIP(Weapon("меч", 12))
PRINT: "[OBJ_HERO.STR_NAME] бьёт на [OBJ_HERO.OBJ_WEAPON.INT_DAMAGE]"

Читается это так: CLASS Имя: ... END описывает поля (обычные ТИП_ИМЯ = значение_по_умолчанию) и методы (обычные FUNC внутри тела класса). Создать экземпляр — просто вызвать имя класса как функцию, точно как в Python: Player("Ая"). Если внутри класса объявлен метод INIT, он сыграет роль конструктора и получит переданные аргументы.

Внутри метода объект всегда доступен как SELF. Поля читаются и пишутся через точку — SELF.INT_HP, OBJ_HERO.STR_NAME — и имя поля так же несёт префикс типа, поэтому работает та же типизация и приведение типов, что и для обычных переменных.

И ещё один момент, симметричный массивам, но в обратную сторону: присваивание объекта — по ссылке (OBJ_B = OBJ_A даёт два имени одного и того же экземпляра, а не копию). Наследования в языке сознательно нет — если очень нужно переиспользовать логику, композиция (поле одного класса — объект другого, как OBJ_WEAPON выше) решает эту задачу без лишней сложности.

Обработка ошибок — TRY / CATCH

Если что-то может пойти не так — оберните это в TRY, а не бойтесь заранее:

TRY:
    INT_X = TOINT("не число")
CATCH: STR_ERR
    PRINT: "Поймали: [STR_ERR]"
END

Ошибки всегда сообщают номер строки, так что искать причину долго не придётся: Ошибка (строка 5): ...

Модули — LOAD

Когда один файл становится слишком большим — вынесите часть в отдельный файл и подключите:

LOAD MathX
LOAD geometry_lib

PRINT: "[AVG([4, 8, 15, 16, 23, 42])]"
PRINT: "[CIRCLE_AREA(3.0)]"

LOAD ИМЯ (без двоеточия) ищет файл ИМЯ.umb сначала рядом со скриптом, который его подключает — так работают локальные модули внутри одного проекта. Если там ничего не нашлось, поиск продолжается в папке lib/ рядом с umbrly.exe — это общая для всех проектов «стандартная библиотека» (в комплекте уже есть lib/MathX.umb с парой полезных функций).

Все FUNC/CLASS из найденного файла становятся доступны глобально, без пространств имён — как если бы их код был вставлен прямо на место LOAD. Повторный импорт одного и того же модуля (в том числе по кругу, через цепочку других LOAD) тихо схлопывается в пустоту — функции не регистрируются дважды.

LOAD допустим только на верхнем уровне файла (не внутри IF/WHILE/FUNC) и разрешается ещё на этапе загрузки файла — до выполнения и до компиляции, поэтому ведёт себя одинаково что в -r, что в -b/-c.

Запуск и компиляция — umbrly.exe

Umbrly можно не только интерпретировать, но и собрать в настоящий нативный .exe — через встроенный транспилятор в C++ и вызов g++ (нужен установленный MinGW-w64/MSYS2). Вот полный набор команд:

КомандаЧто делает
umbrly file.umbзапустить через интерпретатор (короткая форма -r)
umbrly -r file.umb / run file.umbзапуск через интерпретатор
umbrly -b file.umb [out.exe] / build / compileсобрать нативный .exe (нужен g++/MinGW-w64)
umbrly -c file.umb [out.cpp]транспилировать в C++ без вызова g++ — удобно посмотреть, что получилось
umbrly -t file.umbтолько проверить синтаксис (лексер + парсер), без выполнения
umbrly -ir file.umbнапечатать AST программы в текстовом виде
umbrly -d file.umb / -trace file.umbзапустить с построчной трассировкой выполнения
umbrly -v / --versionверсия
umbrly -h / --helpкраткая справка
umbrly --infoинформация о языке и бэкенде компиляции
umbrlyбез аргументов — интерактивный REPL

Компилятор превращает управляющие конструкции (IF/WHILE/FOR/FUNC/TRY и другие) в нативный C++ напрямую, а вызовы встроенных функций и методов классов по-прежнему идут через тот же интерпретатор, что и в режиме -r — это значит, что поведение между интерпретируемым и скомпилированным запуском совпадает один в один, и логика не дублируется в двух местах.

umbrly.exe должен оставаться рядом с папками include/ и src/ — они нужны ему для сборки -b/-c. Упаковка проекта (-p/pack) пока не реализована — это отдельная будущая задача.
